## Exact contracts and flow

Extension integration note, implemented: `listVersioned`/`peekListVersioned` expose monotonic `revision` provenance paired with the cached first page. Store it in navigation `listRevision`. A successful provider revalidation increments it; a cache hit does not. On changed revision, replace old membership and pagination cursor instead of merging stale extra pages. On unchanged revision, keep restored pages. `rememberNavigation` rejects snapshots whose list revision has already been superseded. No duplicate extension freshness clock or object-identity comparison is needed. Cached statistics peek returns only retained complete numeric successes without starting provider work.

`RepositoryDirectory.metadata(hosted: HostedRepository, id: string): Effect<PullRequestDetails, DiscoveryError>` uses the optional provider `getPullRequestMetadata`, falling back to existing details. Azure's implementation reads metadata only. Legacy `RepositoryDirectory.details` deliberately retains its old behavior, including Azure optional file-count retrieval, for existing callers. New dashboard code must call `metadata`, not `details`.

`RepositoryDirectory.statistics(hosted: HostedRepository, expected: OpenPullRequest): Effect<ChangeStatistics, DiscoveryError | ComparisonChanged>` calls provider `getPullRequestStatistics`. It validates returned provider/repository/PR/revisions against the request. Missing source/revisions or an iteration that no longer matches yields `ComparisonChanged`, not zero. Missing provider capability yields `RepositoryUnavailable`. Both production providers implement the capability.

`ChangeStatistics` and `ComparisonIdentity` export from `@duff/core/git-hosting-provider`. The comparison has `providerId`, `authority`, `targetRepository`, `sourceRepository`, `pullRequestId`, `targetRevision`, `sourceRevision`, `baseRevision`, and `mode: 'merge-base-v1'`. `filesChanged` is `Option<number>`. `lines` is `{ _tag: 'Complete', additions, deletions }` or `{ _tag: 'Unavailable', reason }`, with fixed reasons `unsupported-comparison`, `incomplete-response`, `binary-content`, `work-limit-exceeded`. Counts are nonnegative safe integers. Authentication, rate limits, invalid wire data and transport errors remain typed failures.

`DashboardData` additionally exposes:

- `peekMetadata(hosted,id): Effect<Option<PullRequestDetails>>`, retained success even after a failed refresh.
- `list(hosted,state,force?): Effect<RepositoryPullRequestPage,DiscoveryError>`, cached first page only.
- `peekList(hosted,state): Effect<Option<RepositoryPullRequestPage>>`.
- `listVersioned(hosted,state,force?): Effect<DashboardListResult,DiscoveryError>` and `peekListVersioned(hosted,state): Effect<Option<DashboardListResult>>`; result fields are `page` and `revision`.
- `rememberNavigation(hosted,snapshot): Effect<void,InvalidProviderResponse>` validates at most five pages, 250 unique PR rows, matching repository/filter, selected PR membership, query length at most 1000, and a non-superseded `listRevision`. The row/page bounds are independent so selected-PR metadata recovery may add a row beyond a provider page's ordinary size. Fields: `filter`, `pulls`, `cursor: Option<Redacted<string>>`, `pullRequestId: string` (empty means no selection), `pages`, `query`, `listRevision`.
- `peekNavigation(hosted,filter?): Effect<Option<RepositoryNavigationSnapshot>>`; omitted filter restores the repository's last-used filter. Specifying a filter restores its own loaded pages and selection. It does not fetch or create an entry.
- `peekStatistics(hosted,expected): Effect<Option<ChangeStatistics>>`; exact source/target/repository/PR key, complete numeric values only, no network, no freshness update. With peeked metadata, this supplies immediate totals while metadata revalidates. Changed revisions return no old totals.
- `invalidate(hosted): Effect<void>`, clears that repository's metadata/list association and conservatively clears all lifecycle statistics associations. Call on removal, relocation of the old identity, or reconnect. Cancel selection work first; generation checks also prevent invalidated resource jobs from repopulating retained caches.

Compose `DashboardData.layer.pipe(Layer.provide(repositoryDirectoryLayer))` once. If other runtime clients need the directory too, use the existing composition root's shared layer identity with `Layer.provideMerge` or merge that same directory layer explicitly.

On selection or focus: paint peeked values if available, call metadata/list with `force=false`, render metadata, then always call statistics for the returned PR. A fresh metadata hit must not skip first statistics loading or an eligible unavailable retry. `force=true` bypasses the local 60s metadata/failure/unavailable interval, but not a provider Retry-After. Completed statistics are reused even with `force=true`. Pending automatic/manual calls join the same active lookup; interruption of the last caller interrupts the underlying request. No polling or detached runtime jobs are started.

The extension owns dashboard visibility, active/picker suppression, selection generation, retained stale/refreshing rendering, cancellation on close/switch, and native application of restored navigation. Core owns the bounded navigation snapshot cache; do not add a second extension repository cache. Save updated navigation after pages, filter/query, and PR selection change. Restore it before the shared freshness check; compare list revisions before deciding whether extra pages remain current. Stop pagination at the five-page/250-row budget. Core does not publish UI state. Core bounds: 20 repository entries, one selected metadata record per entry, three filter first pages of at most 50 items each, three full navigation snapshots per repository with at most five pages/250 rows each, and 100 statistics attempts/successes. Azure separately retains at most 100 completed full comparison identities and no raw diff responses. Statistics work is capped at 200 files, five iteration-change pages, batches of ten, and 4 MiB per HTTP JSON response. Work caps are local budgets, not claims about Azure limits.

GitHub metadata still includes its supplied numeric totals with no comparison request. If the dashboard requests typed statistics, the GitHub adapter revalidates selected metadata and resolves the immutable merge base through the compare endpoint, preserving response-supplied totals. That operation can fail separately from already usable metadata totals.
