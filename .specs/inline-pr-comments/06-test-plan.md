## Slice 2: A saved draft survives restart without duplicate posting

1. **Red:** saving a draft through the real SQLite adapter, disposing and reconstructing it retains exact body/target/version outside the repository. **Green:** private new store and Schema codecs. **Refactor:** one canonical persistence projection.
2. **Red:** two adapter instances saving the same expected revision admit only one; losing text is not overwritten; a draft targeted to PR A cannot become PR B on activation. **Green:** transactional CAS and immutable destination. **Refactor:** no process-local lock masquerading as interprocess safety.
3. **Red:** native document changes while an earlier save is blocked acknowledge only the saved bytes; newest version eventually persists. Ctrl-S and autosave cannot race independent writes. **Green:** per-draft serialized document.save loop with exact bytes in writeFile. **Refactor:** single save path.
4. **Red:** Send flush failure produces no provider write; double-click Send reserves once; confirmed send clears only sent version while newer edits remain. **Green:** prepare/dispatch/finish transactions. **Refactor:** explicit states instead of boolean busy flags.
5. **Red:** recorded GitHub REST create uses exact head `commit_id`, path/right line and only submitted body; reply uses root ID, not reply ID. Old snapshot/base-side/multi-line creation is rejected **before dispatch**, with draft retained. **Green:** bounded supported protocol mapping. **Refactor:** keep unsupported cases explicit.
6. **Red:** Azure create uses matched iteration IDs/changeTrackingId and exact side/line offset 0; response revision/anchor mismatch does not trigger corrective repost. **Green:** provider create and receipt warning. **Refactor:** share only domain outcome, not wire DTOs.
7. **Red:** lost transport response, 408/5xx, successful malformed/oversize body, ambiguous GraphQL errors and cancellation after dispatch leave recoverable uncertainty. Restart performs zero automatic writes. **Green:** mutation transport and journal recovery. **Refactor:** never reuse query POST error semantics blindly.
8. **Red:** crash/fault injection at Prepared, Dispatching, remote success, receipt commit and draft deletion boundaries preserves recovery evidence. Known remote success plus failed read is “posted/refresh failed”; failed outcome commit cannot invite retry. **Green:** guarded transitions and atomic unchanged-version deletion. **Refactor:** avoid a network-spanning transaction.
9. **Red:** uncertainty blocks sends across two store instances until explicit warning acknowledgment; missing bounded-list result or matching body cannot prove rejection. **Green:** persisted target reservation and deliberate release. **Refactor:** no hidden retry worker.

Use Effect Deferred/TestClock or explicit recording seam barriers, not sleep-based race tests. Storage crash claims require a child process against a real temp SQLite file, terminated at controlled barriers then reopened; an in-memory state-machine test alone is insufficient. Permission/busy/corrupt/unknown-schema/private-file failures preserve existing data and never fall back to memory.

Native qualification gate: writable opaque draft URI opens beside diff, edits automatically save, close/reopen/reload/full editor restart recovers acknowledged text and original target. Hiding comments and PR switching preserve drafts. Test Save failure/readonly disk with retained dirty text, explicit recovery controls and disabled Send. Test edits made during Send remain after completion, and no obsolete draft document recreates a cleared sent record. Use new draft IDs or a read-only sent receipt tab after send; never auto-recreate deleted IDs from late file-system writes.
